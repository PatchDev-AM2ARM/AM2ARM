# AM2ARM Linux runtime

The launcher ships 153 ARM64 ELF files for its installer, and gmloader-next with its libraries under `AM2ARM/gmloader/`. The installer builds the game with the player's original AM2R 1.1 Windows ZIP. The firmware supplies the physical display, audio and input drivers.

[inventory.tsv](inventory.tsv) lists each installer ELF by location, architecture, byte count, SHA-256, provider and direct ELF library requirements. Paths start at the managed `AM2ARM/` directory. `sha256_before_packaging_strip` identifies the original Debian file or unstripped build output where available. A dash means that only the final binary hash is recorded. ELF type `DYN` covers shared libraries and position-independent executables. Libraries loaded with `dlopen` or passed by a launcher argument do not appear in the ELF requirements column.

[debian.tsv](debian.tsv) identifies the 58 contributing Debian binary packages with the exact version, source package, upstream source link, original package SHA-256, purpose and packaged copyright file. The notice path starts at `AM2ARM/`. The copy of `xkbcomp` matches the original Debian binary after `llvm-strip --strip-unneeded`. Each archived package was checked against the Debian 12 ARM64 Packages index, SHA-256 `2ddb1737692e8c45c53e8d57c0ce4cd21c78c5703b830c3226b1423566a06c00`, authenticated by the Debian archive and stable-release keys.

`AM2ARM/gmloader/SOURCES.txt` gives the exact gmloader-next commit, the SDL release and the Debian packages of the libraries in `gmloader/fallback`. Their notices are in `gmloader/licenses`. [Build](../../../gmloader/README.txt)

## What runs on each display route

| Component | Consumer and alternatives |
| --- | --- |
| Python 3.11, Tcl/Tk, X11, fonts, Python extension modules and their support libraries | The launcher uses Python for route selection, setup and starting the game. Tk and its X11 libraries provide the offline installer. The xdelta3 executable reconstructs the game data. A firmware interpreter alone does not establish support for the same Tk, compression, hashing and foreign-function modules. |
| `runtime/core/` and `runtime/lib/libstdc++.so.6`, `libgcc_s.so.1` | The launcher calls the paired Debian glibc 2.36 loader for its own Python. The direct-display installer calls that loader per child process and puts its own core and support libraries ahead of firmware paths. On the Wayland installer path the firmware loader runs the packaged Python/Xwayland with `runtime/lib`. The game uses none of them. |
| Installer `runtime/bin/Xwayland` and `xkbcomp.bin` | An existing Wayland socket supplies the compositor. The installer starts a private X server with a cookie and TCP disabled. Its local patch requests a fullscreen 640×480 root window on the selected output. Substituting the system X server must preserve dimensions, placement, keyboard lookup, focus and exit cleanup. |
| `runtime/bin/Xvfb` | On recognized direct-display boards it provides a private X screen for Tk. The installer copies its X framebuffer into a firmware SDL window. A system Xvfb is a candidate where its XKB paths, fonts, access control and supported options are available. |
| `gmloader/gmloadernext.aarch64`, `gmloader/lib` | gmloader-next runs the Android build of the game with the firmware's SDL2, EGL, GLES2 and audio. `libdualscreen.so` opens the second window. `librumble.so` is preloaded on the Brick and Smart Pro, whose motor the launcher drives. `lib/arm64-v8a` holds the Android C and C++ libraries the game links. |
| `gmloader/fallback` | SDL2 and Wayland client libraries. The launcher links each one in only where the firmware has no ARM64 copy. |

These components stay under the launcher directory. The package supplies no Mali, Mesa, GBM or EGL driver. A matching filename by itself does not establish ABI or display compatibility.

The 99 filenames in the launcher's `runtime/lib/` represent 61 distinct binaries. The remaining entries reproduce Debian library aliases as ordinary files for game cards.
